## Problem

A service that must tell another system about a change has a dual-write gap: commit then send loses the message on a crash; send then commit sends a message for a fact that rolled back. The transactional outbox closes the gap (write the message in the business transaction, deliver it after commit), but the delivery half is where libraries differ, and the failures are silent:

- pg-txmode's old `relay` marked a row published **when it claimed it**, so a crash between claim and send lost the message (fixed by pg-txmode spec 0004).
- Effect 4.1's `PersistedQueue` fences a stale worker **silently** (the stale `take` returns success), does not require a transaction on `offer`, has no ack in the caller's transaction, stores `Cause.pretty` text as the failure, and ends a row after `maxAttempts` whatever the cause (pg-txmode spec 0005, `docs/evidence/persisted-queue/`).
- Everything with `LISTEN` or a session advisory lock leaks on PgBouncer and is unsupported on Hyperdrive (pg-txmode catalogue rows `listen`, `advisory-session`).

No library in the research's landscape states the protocol, its model and its pooler evidence together. This one does, and it is **not a queue runtime**.

## Goal

A client-neutral core (no Effect, no driver) that states the outbox protocol once, as data, in five parts that derive from one declaration:

1. the **schema** and its migration (SQL as constructs);
2. the **statements** of the protocol with typed results (claim by id, claim a batch, ack, release, bury, hold, receipt, sweep, report, cleanup);
3. the **mode check**: every operation names the pg-txmode catalogue rows it rests on, and an `unverified` cell is refused unless the caller accepts it;
4. a **conformance suite** that runs each falsifier on PostgreSQL directly and behind PgBouncer in transaction mode, each with a negative control that must fail;
5. a **TLA+ model** of the claim and fence protocol with broken variants that TLC must reject, tied to the code by operation id and by a digest of the covered files.

Adapters (specs 0002 and 0003) put a `pg` function set and an Effect service on the statements; they add no SQL.

## Journey

```text
declare once     const outbox = declareOutbox({ table: "outbox", kinds: ["Mail", …], errorClasses: ["rejected", "timeout", …],
                                                retry: { maxAttempts: 8, delaysMs: [300_000, …, 43_200_000] } })
migrate          outbox.migration         → ordered CREATE statements (the caller's migration tool runs them)
1. in the command's transaction (requires one)
                 outbox.enqueue({ kind, payload, dedupeKey?, now })           → Enqueued(id) | Duplicate
2. after commit, a wake-up (the caller's: a queue message with the id, a cron tick, a nudge). No LISTEN.
3. outbox.claimById({ id, leaseMs, now })                                      → Claimed(row, token, attempts) | Held(ms) | NotDue(ms) | Settled
   outbox.claimBatch({ limit, leaseMs, now })                                  → Claimed[]          [SKIP LOCKED: unverified on Hyperdrive]
4. send (idempotency key: the row id; fencing number: attempts)
   outbox.ack({ id, token, now })                                              → Delivered | ClaimLost       [joins the caller's transaction]
   outbox.release({ id, token, attempts, errorClass?, retryAfterMs?, now })    → Released | Buried | ClaimLost
   outbox.bury({ id, token, errorClass, now })                                 → Buried | ClaimLost
   outbox.holdClaim({ id, token })                                             → Holding | ClaimLost         [requires a transaction]
5. a worker that dies leaves the lease to lapse; the row is claimed again.
   outbox.markQueued({ ids, now }) records the transport's receipt; outbox.stale({ olderThanMs, limit, now }) lists rows no receipt covers.
6. outbox.counts, outbox.open({ limit }) (never the payload); outbox.cleanup({ olderThanMs, limit, now }) deletes terminal rows.
```

Each builder returns a `Statement<A>`: `{ operation, text, values, decode }`. An adapter runs `text` with `values` on its driver and hands the rows to `decode`, which says `{ done, value }` or `{ next }` (a claim by id that matched nothing asks the table why, so a second statement runs). The loop is five lines in each adapter and the protocol is in none.

## The clock is an argument

Leases compare clocks (research R11). Every statement that compares or records time takes a `now: Now` argument, and the SQL uses it as `COALESCE($n::timestamptz, statement_timestamp())`:

| `Now` | Meaning | Use |
| --- | --- | --- |
| `databaseNow` (`{ source: "database" }`) | the bind parameter is null: the database's `statement_timestamp()` | the **default of the adapters** |
| `fixedNow(at)` | the caller's instant, as ISO text | tests; an Effect adapter that takes the time from `Clock` so `TestClock` controls it (vektorprogrammet's precedent) |

Why the database clock is the adapters' default: every consumer that uses it agrees with every other, whatever its host's clock says (no skew by construction). The cost is that a test cannot move it (a lease of 0 ms stands for a lapsed one, or the test uses `fixedNow`). Why it is a parameter and not a surprise: the core's statements contain no other clock (`now()`, `clock_timestamp()`, `CURRENT_TIMESTAMP` are absent, and a test fails when one appears); the caller names the clock at the boundary.

The skew risk of `fixedNow`: consumers on hosts whose clocks differ by more than the lease can hold one row at the same moment, and a clock that steps back extends leases. With a fixed clock the lease must be much longer than the skew the deployment accepts. The fence protects the row whatever the clock does (a stale token changes nothing); `attempts` is the fencing number for a downstream system. Do not mix the two clocks on one table: a lease that one consumer wrote with its own clock is judged by the other with the database's.

## Guarantees

LS1 to LS5 are the operator's own (vektorprogrammet `store-guarantees.md`), stated as properties of the store, with where each is held here:

| Id | Property | Held by | Falsifier |
| --- | --- | --- | --- |
| LS1 | A pending row has at most one live claim; of any number of claimers exactly one holds it. A duplicate finds `Held` or `Settled` and never sends twice. | `claimById`: one conditional `UPDATE` (the live-claim condition); `claimBatch`: the same condition and `SKIP LOCKED` | F2 |
| LS2 | An ack, release, bury or hold that carries a token other than the row's current one changes nothing and reports `ClaimLost`; a hold that succeeds keeps the row locked to the end of the caller's transaction, so another consumer's claim waits. | the token condition in each settle statement; `FOR NO KEY UPDATE` in the hold | F3, F4 |
| LS3 | Delivery is at least once, with no order across rows; a provider can hear of a row twice when its send succeeded and the ack did not commit. | a claim never marks the row delivered; the lease lapses | F6 |
| LS4 | `ack` is one conditional write that joins the caller's transaction when there is one. | one statement, no session state | F5 |
| LS5 | Receipts and a sweep wake a row without `LISTEN`; a row ends `dead` only after a recorded failure class (and, in `release`, after the declared attempts). | `queued_at`, `stale`, the `dead` CHECK, the `release` statement | F7, F9 |

`claim_token` is identity; `attempts` rises at each claim, so it is the **monotonic fencing number** that a downstream system can check (Kleppmann, "How to do distributed locking"). The fence protects the row, not the world: a worker that outlives its lease can still do its side effects, and only a system that checks the number can refuse them.

## The schema

A declaration yields one table (the name is validated as a simple lower-case identifier and quoted, so no statement needs escaping):

```sql
CREATE TABLE "outbox" (
  id              bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  kind            text        NOT NULL,                -- CHECK (kind IN (…)) when the declaration lists the kinds
  dedupe_key      text,
  payload         jsonb       NOT NULL,
  status          text        NOT NULL DEFAULT 'pending',
  attempts        integer     NOT NULL DEFAULT 0,
  claim_token     uuid,
  claimed_until   timestamptz,
  next_attempt_at timestamptz NOT NULL,                -- no default: `enqueue` writes the caller's `now`
  queued_at       timestamptz,                         -- the transport's receipt
  settled_at      timestamptz,                         -- set when the row is delivered or dead
  last_error      text,                                -- a class of the declaration's closed set, never provider text
  created_at      timestamptz NOT NULL,                -- no default, as above
  CONSTRAINT outbox_status       CHECK (status IN ('pending', 'delivered', 'dead')),
  CONSTRAINT outbox_attempts     CHECK (attempts >= 0),
  CONSTRAINT outbox_lease        CHECK ((claim_token IS NULL) = (claimed_until IS NULL)),
  CONSTRAINT outbox_claim_open   CHECK (claim_token IS NULL OR status = 'pending'),
  CONSTRAINT outbox_settled      CHECK ((status = 'pending') = (settled_at IS NULL)),
  CONSTRAINT outbox_dead_class   CHECK (status <> 'dead' OR last_error IS NOT NULL),
  CONSTRAINT outbox_error_class  CHECK (last_error IS NULL OR last_error IN (…))
);
CREATE INDEX outbox_due ON "outbox" (next_attempt_at) WHERE status = 'pending';
CREATE UNIQUE INDEX outbox_dedupe ON "outbox" (kind, dedupe_key) WHERE dedupe_key IS NOT NULL;
COMMENT ON TABLE "outbox" IS 'pg-outbox schema 1';
```

Differences from the research's sketch, each with its reason: `settled_at` replaces `delivered_at` (one timestamp for both endings, so retention has one clock; the `delivered iff` CHECK becomes `pending iff unsettled`); `outbox_claim_open` (a token or lease only exists on a pending row, so the `status = 'pending'` conditions of the settle statements are defence, not load-bearing, and the table cannot hold a claimed delivered row); `last_error` is CHECKed against the declaration's closed set (F13 is store-enforced, not only typed); no default clock (the clock is the caller's argument).

## The statements

Durations are bind parameters in milliseconds, used as `$n::float8 * interval '1 millisecond'`; every time is `instant(n)`, the `Now` of the call.

| Operation | Statement (shape) | Result | Transaction | Catalogue rows | Read |
| --- | --- | --- | --- | --- | --- |
| `enqueue` | `INSERT … ON CONFLICT (kind, dedupe_key) WHERE dedupe_key IS NOT NULL DO NOTHING RETURNING id` | `Enqueued(id)` / `Duplicate` | **requires** | `on-conflict` | no |
| `claimById` | `UPDATE … SET claim_token = gen_random_uuid(), claimed_until = now + lease, attempts = attempts + 1 WHERE id = $1 AND status = 'pending' AND next_attempt_at <= now AND (claimed_until IS NULL OR claimed_until <= now) RETURNING …` | row, or none → `classify` | standalone | `outbox-lease` | no |
| `classify` (after a miss) | `SELECT status, ms until the lease ends, ms until due FROM … WHERE id = $1` | `Held(ms)` / `NotDue(ms)` / `Settled` | standalone | `outbox-lease` | **yes** |
| `claimBatch` | `WITH due AS (SELECT id … ORDER BY next_attempt_at, id FOR UPDATE SKIP LOCKED LIMIT $1) UPDATE … FROM due …` | rows | standalone | `outbox-lease`, `skip-locked` | no |
| `ack` | `UPDATE … SET status = 'delivered', settled_at = now, token = NULL … WHERE id = $1 AND claim_token = $2 AND status = 'pending'` | `Delivered` / `ClaimLost` | **joins** | `outbox-lease` | no |
| `release` | one `UPDATE` that clears the claim, records the class (`COALESCE($3, last_error)`), and either moves `next_attempt_at` or, when `attempts >= $maxAttempts` **and** a class is on record, ends the row `dead` | `Released` / `Buried` / `ClaimLost` | joins | `outbox-lease` | no |
| `bury` | `UPDATE … SET status = 'dead', last_error = $3 … WHERE id = $1 AND claim_token = $2` | `Buried` / `ClaimLost` | joins | `outbox-lease` | no |
| `holdClaim` | `SELECT id … WHERE id = $1 AND claim_token = $2 AND status = 'pending' FOR NO KEY UPDATE` | `Holding` / `ClaimLost` | **requires** | `row-locks` | no |
| `markQueued` | `UPDATE … SET queued_at = now WHERE id IN (the ids) AND status = 'pending'` | count | standalone | `outbox-lease` | no |
| `stale` | `SELECT id … WHERE status = 'pending' AND no live claim AND greatest(coalesce(queued_at, created_at), next_attempt_at) <= now - $1 ORDER BY id LIMIT $2` | ids | standalone | `outbox-lease` | **yes** |
| `counts` | `SELECT status, count(*) … GROUP BY status` | counts | standalone | `outbox-lease` | **yes** |
| `open` | `SELECT id, kind, attempts, last_error, ms held, ms until due … WHERE status = 'pending' ORDER BY id DESC LIMIT $1` | rows, never the payload | standalone | `outbox-lease` | **yes** |
| `cleanup` | `DELETE … WHERE id IN (SELECT id … WHERE status IN ('delivered', 'dead') AND settled_at <= now - $1 ORDER BY id LIMIT $2)` | count | standalone | `outbox-lease` | no |

**Transaction column** (one declaration, `operations.ts`, read by the mode check, the suite and the docs). `requires`: meaningless outside the caller's transaction (`enqueue` commits alone otherwise, which is the dual-write gap; a hold outside one holds nothing); an adapter takes the transaction as a parameter or in its type. `joins`: one conditional write that commits with the caller's transaction when there is one and alone otherwise. `standalone`: must **not** run in a caller's transaction: a claim that sits in an open transaction is invisible to every other claimer until it ends, and holds its row lock while the worker sends.

**Ids, tokens, payloads.** An id is a branded decimal string (`bigint` exceeds `Number`); a token is a branded string; `payload` is sent as `$n::jsonb` text and read back as `payload::text`, so no driver's JSON rule decides the encoding. Timestamps never come back: the statements return milliseconds. A row that does not have the promised shape (zod, at the edge of the library) is a `ProtocolError` that names columns and never values (a payload can hold personal data): a defect of the deployment, not an answer. A kind or class that the declaration does not know, read from a row, is a `ProtocolError` too; given as an argument, an `InvalidArgumentError`.

**`release` and the attempt policy.** `retry: { maxAttempts, delaysMs }` is data in the declaration. After a failed send the worker calls `release` with the class it observed, or none when no provider produced one (an outage on the worker's own side). The row ends `dead` only when `attempts >= maxAttempts` **and** a class is on record (this call's or an earlier one's); an outage never burns a row (vektorprogrammet spec 0008b R2). A poison payload is `bury`'d at once with its class. The next attempt is due after `delaysMs[min(attempts, n) - 1]` (or the caller's `retryAfterMs`). Both `release` and `bury` clear the claim.

**The closed set of classes.** `errorClasses` is a non-empty list in the declaration, a union type in the API, and a CHECK in the table. There is no way to store `String(error)`.

## The mode check

Each operation lists the catalogue rows it rests on (table above). `operationSupport(mode, id)` is the weakest cell of its rows in the mode's column **that is evidence for this mode and this use**: a cell that Supavisor inherits from PgBouncer's column (no Supavisor ran) and a use that the cell's recorded run did not cover (`coverageGaps`: `enqueue` is a concurrent `ON CONFLICT DO NOTHING` with one winner, which the Hyperdrive run did not include) are `unverified`, whatever the cell says (`works` is `yes`, `unknown` is `unverified`, anything else is `no`; pg-txmode keeps that mapping private, so it is repeated in one function and a test pins it to `capabilities` for every row that has a feature name), and a **read** is capped at `unverified` on a mode whose `capabilities(mode).cachesReads` is true (Hyperdrive: reads are cached and a write does not purge them). `requireOperation(mode, id, { allowUnverified })` throws `UnsupportedOperationError`, quoting the catalogue cell. Every read statement calls `statement_timestamp()`, which Hyperdrive's documentation lists among the functions that make it skip its cache; nothing was run through Hyperdrive, so the cell stays `unverified`. A claim by id works wherever PgBouncer does and is the Hyperdrive-safe claim (it uses no `SKIP LOCKED`); a batch claim is `unverified` there. On Hyperdrive today only `enqueue` (`on-conflict`) is `yes`.

## What is not supported

`LISTEN/NOTIFY`, session advisory locks, logical replication, `COPY`, named prepared statements that the pooler does not track (F8 lints every statement in every mode); a worker runtime, cron, flows, dashboards, rate limits (use Effect's queue or effect-mq); ordering across rows or per key (delivery is unordered; a later spec can add a per-key rule); exactly-once delivery (effects must be idempotent; the row id is the key); broker clients in the core (a transport publishes ids after commit and the receipt is recorded with `markQueued`); payload encryption and personal-data policy (the caller owns what goes into `payload`); an inbox (exactly-once processing); databases other than PostgreSQL; concurrency claims on PGlite (it runs every statement on one session, so races prove nothing there); isolation levels above READ COMMITTED (the fence relies on a second claimer re-reading the row after the lock wait; under REPEATABLE READ the loser gets 40001 instead of an empty result).

## The model

`model/ClaimFence.tla` models one row, `Workers` workers and a clock. Each action is tagged `\* @operation <id>` with the operation it models: `Claim` (claimById, claimBatch), `Ack`, `CommitAck` (ack), `Release`, `Bury`, `Hold` (holdClaim); `Tick`, `Send`, `EndTx`, `Crash`, `ClaimWaits` and `ClaimHeld` are the world and the observation points of the reach cases. The other seven operations are listed in `model/cases.json` as not modelled, each with its reason. Six switches (`Fence`, `LiveCheck`, `MarkAtClaim`, `ClassRule`, `HoldLocks`, `LeaseLapses`) turn one rule off each. Invariants: `AtMostOneLiveLease` (LS1), `NoStaleSettle` and `HoldExcludesClaims` (LS2), `DeliveredWasHeard` (LS3), `DeadNeedsClass` and `ReleaseEndsAfterAttempts` (LS5), `LeaseIsFinite`.

`model/cases.json` lists every TLC run: `current-code` (every rule on, every invariant), six `broken` variants (one rule off; must violate the invariant it names, alone and as the first one TLC reports with every invariant checked (others may fail on longer traces: not checked); each names the id of the conformance control that makes the same defect in SQL), and eight `reach` cases (the model can reach a lost claim, a held row, a hold that makes a claim wait, a delivery, a dead row, a reclaim, a death by release and a row heard twice: a pass of `current-code` over a model that cannot do these would mean nothing). `bun run model` (in `ready` and CI) runs TLC (2.19, from `devenv.nix`) on each and fails when the correct model has an error, a broken variant has none or another, or a reach case finds nothing.

The tie to the SQL (a **test-rung** edge, not generated): `tools/model/test/tie.test.ts` fails when an operation tag in the model is not an operation of `operations.ts`, when an operation is neither tagged nor listed as not modelled, or when a control id of `cases.json` is not the id of a control of the suite; `bun run model` fails when the digest of `decode.ts`, `now.ts`, `operations.ts`, `outbox.ts`, `schema.ts` and `sql.ts` is not the one recorded in `model/confirmed.json` (`bun tools/model/run.ts --digest` prints it), so a change to a statement stops the build until the model's action for it is read again and the digest is re-recorded by hand. TLC checks the model; it does not check the SQL. The model is not generated from the declaration (a decision: the correspondence between a TLA+ action and a SQL statement is a reviewed claim). Its size is two workers, four ticks, three claims: 115,572 distinct states for the correct model.

## Falsifiers

Each runs on PostgreSQL directly and behind PgBouncer in transaction mode (Neon's settings, three server connections, so concurrent clients really swap connections). A race runs `PG_OUTBOX_ROUNDS` fresh rounds (default 100; 300 for the heavy run) on a freshly created table and prints the loser's `Cause` when it fails. A negative control is a mutation of the statement text (applied by the test subject at the point where it sends; never to the product source) that **must** make the falsifier fail; a rewrite that changes nothing fails the suite (no vacuous control), and a control that fails because its SQL is malformed (class 42) fails the suite too. Each control's first failure line is printed.

| # | Falsifier (must hold) | Negative control (must fail) |
| --- | --- | --- |
| F1 | A rolled-back business transaction leaves no row; a committed one leaves one, with its id | `enqueue` on its own connection: the row survives the rollback |
| F2 | Of 20 concurrent claimers of one row exactly one gets `Claimed`, the rest `Held`; batch claimers take disjoint sets that add up to every row; a row locked by an open transaction is skipped by a batch claim, which takes the next row instead of waiting | remove the live-claim condition from `claimById`; remove it from `claimBatch`; remove `SKIP LOCKED` |
| F3 | After the lease lapsed and a second claimer took the row, the first claimer's `ack`, `release`, `bury` and `holdClaim` all answer `ClaimLost` and change nothing; a lapsed lease that nobody took over does not stale its token | each of `ack`, `release`, `bury` without the token condition |
| F4 | A hold inside a transaction keeps the row locked: a competing claim waits until the transaction ends and then takes the row (not acked) or finds it `Settled` (acked); a stale token's hold answers `ClaimLost` | a hold that locks nothing (`SELECT` without `FOR NO KEY UPDATE`); a hold without the token condition (round 1) |
| F5 | `ack` in the caller's transaction: its rollback rolls the ack back; its commit commits both | `ack` on its own connection: it survives the rollback |
| F6 | A worker that claims and never acks does not lose the row: it is claimed again after the lease (`attempts` 2, a new token); while the lease is live nobody else gets it; the same on the database clock with a real 300 ms lease | a claim that marks the row delivered (the old relay); a lease that never lapses |
| F7 | A class is recorded and the next attempt waits for its date (both claims); the row ends `dead` only when `attempts >= maxAttempts` **and** a class is on record; five failures with no class never end it; `bury` records its class; the table refuses a dead row with no class | end the row by attempt count alone; end it by the class alone; ignore the retry delay (the last two: round 1); drop `next_attempt_at <= now` from each claim |
| F8 | Every statement of the library (the log of a full journey, each text on its own, the migration) passes `@pg-txmode/lint` with no error in seven modes (direct, session-pooled, Hyperdrive, PgBouncer with and without tracked statements, Neon, Supavisor) | add a `LISTEN`; add a session advisory lock: the lint fails |
| F9 | `markQueued` records the receipt for pending rows only; the sweep lists a pending row with no live claim and no recent receipt, and stays quiet until the threshold has passed after the receipt | the sweep without the receipt term lists the row again at once |
| F10 | `cleanup` deletes only terminal rows older than the TTL, at most `limit` at a time, never a pending or claimed row | a cleanup keyed on creation time with no status filter |
| F11 | The model: the correct configuration has no error; each broken variant has the counterexample its case names; each reach case finds its state; the operation ids of the model and of the code are the same set; the covered digest is current | the broken variants themselves; an operation removed from the tags |
| F12 | The mode check: PgBouncer, Neon and direct accept every operation; Hyperdrive and Supavisor refuse every operation as `unverified` (their evidence is another mode's or another use's) unless `allowUnverified` is set; every read statement calls an uncached function (`uncachedFunctions` of the lint). Status of the Hyperdrive **behaviour**: unverified, nothing was run through it | a read with no uncached function (`stale` with its time parameter replaced by a bare column) |
| F13 | `last_error` holds only a class of the closed set: the store refuses another text (23514), and the declaration refuses a class outside its set | a migration without the CHECK accepts an address |

## Constraints on the implementation

- Free on mechanism, specific on behaviour: the statements may change as long as the journey and the falsifiers hold.
- Tests wait for the server's own clock only where a lease must lapse for real (a 300 ms lease, then 450 ms); everywhere else the lease lapses by arithmetic on `fixedNow`.
- Nothing is published; every package is private.

## Risks

| Risk | Mitigation |
| --- | --- |
| Hyperdrive was not tried: its read cache, `claimById`, `FOR NO KEY UPDATE` and `ON CONFLICT` through it are unverified for this table | Every Hyperdrive cell says `unverified` and the mode check refuses it by default; the claim by id avoids the one unverified construct; pg-txmode's probe Worker (a wizard) is the only source of truth |
| The model is a claim about the SQL, not a proof of it | Said; the tie is by id and by digest, and every broken variant has a SQL control in the conformance suite |
| The submodule pin hides changes in pg-txmode | Moving the pin is a reviewed diff; the catalogue rows each operation rests on are named in `operations.ts`; the trigger that retires the submodule is named above |
| A clock that steps back, or hosts that disagree under `fixedNow`, extend or duplicate leases | The clock is an argument; the database clock is the adapters' default; the fence and `attempts` are the protection that does not depend on a clock |
| A claim by id costs a second statement on a miss | Only on a miss; the second is a read of one row by primary key |
| `Held` after a race may report 0 ms (the claim was released between the two statements) | Documented in the result; the caller looks again |
| TLC and Java 8 enter the default devenv shell (CI downloads them) | They make `ready` one command; a profile like vektorprogrammet's `formal` would keep them out, at the price of a second shell for `ready` |
