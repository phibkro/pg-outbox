## Problem

A service that must tell another system about a change has a dual-write gap: commit then send loses the message on a crash; send then commit sends a message for a fact that rolled back. The transactional outbox closes the gap (write the message in the business transaction, deliver it after commit), but the delivery half is where libraries differ, and the failures are silent:

- pg-txmode's old `relay` marked a row published **when it claimed it**, so a crash between claim and send lost the message (fixed by pg-txmode spec 0004).
- Effect 4.1's `PersistedQueue` fences a stale worker **silently** (the stale `take` returns success), does not require a transaction on `offer`, has no ack in the caller's transaction, stores `Cause.pretty` text as the failure, and ends a row after `maxAttempts` whatever the cause (spec 0005, `docs/evidence/persisted-queue/` in pg-txmode).
- Everything with `LISTEN` or a session advisory lock leaks on PgBouncer and is unsupported on Hyperdrive (pg-txmode catalogue rows `listen`, `advisory-session`).

No library in the research's landscape states the protocol, its model and its pooler evidence together. This one does, and it is **not a queue runtime**.

## Goal

A client-neutral core (no Effect, no driver) that states the outbox protocol once, as data, in five parts that derive from one declaration:

1. the **schema** and its migration (SQL as constructs);
2. the **statements** of the protocol with typed results (claim by id, claim a batch, ack, release, bury, hold, receipt, sweep, report, cleanup);
3. the **mode check**: every operation names the pg-txmode catalogue rows it rests on, and an `unverified` cell is refused unless the caller accepts it;
4. a **conformance suite** that runs each falsifier on PostgreSQL directly and behind PgBouncer in transaction mode, each with a negative control that must fail;
5. a **TLA+ model** of the claim and fence protocol with broken variants that TLC must reject, tied to the code by operation id and by a digest of the covered files.

Adapters (specs 0002 and 0003) put a `pg` function set and an Effect service on the statements; they add no SQL.

## Journey

```text
declare once        const outbox = declareOutbox({ table: "outbox", kinds: [...], errorClasses: ["timeout", "rejected"],
                                                   retry: { maxAttempts: 8, delaysMs: [300_000, …, 43_200_000] } })
migrate             outbox.migration            → ordered CREATE statements (the caller's migration tool runs them)
1. in the command's transaction
                    outbox.enqueue({ kind, payload, dedupeKey? })       → Enqueued(id) | Duplicate          [requires a transaction]
2. after commit, a wake-up (the caller's: a queue message with the id, a cron tick, a nudge). No LISTEN.
3. outbox.claimById({ id, leaseMs })                                    → Claimed(row, token, attempts) | Held | NotDue | Settled
   outbox.claimBatch({ limit, leaseMs })                                → Claimed[]                          [SKIP LOCKED: unverified on Hyperdrive]
4. send (an idempotency key: the row id; a fencing number: attempts)
   outbox.ack({ id, token })                                            → Delivered | ClaimLost              [joins the caller's transaction]
   outbox.release({ id, token, errorClass? })                           → Released | Buried | ClaimLost
   outbox.bury({ id, token, errorClass })                               → Buried | ClaimLost
   outbox.holdClaim({ id, token })  (in the caller's transaction)       → Held | ClaimLost                   [row lock to the end of the transaction]
5. a worker that dies leaves the lease to lapse; the row is claimed again.
   outbox.markQueued({ ids }) records the transport's receipt; outbox.stale({ olderThanMs, limit }) lists rows no receipt covers.
6. outbox.counts, outbox.open({ limit }) (never the payload); outbox.cleanup({ olderThanMs, limit }) deletes terminal rows.
```

Each of those is a `Statement<A>`: `{ id, text, values, decode }`. An adapter runs `text` with `values` on its driver and hands the rows to `decode`. A claim by id is two statements (the conditional `UPDATE`, then, on a miss, a classifying read): `decode` returns `{ done }` or `{ next }`, so the loop is five lines in each adapter and the protocol is in none.

## Guarantees

LS1 to LS5 are the operator's own (vektorprogrammet `store-guarantees.md`), stated as properties of the store, with where each is held here:

| Id | Property | Held by | Falsifier |
| --- | --- | --- | --- |
| LS1 | A pending row has at most one live claim; of any number of claimers exactly one holds it. A duplicate finds `Held` or `Settled` and never sends twice. | `claimById`: one conditional `UPDATE` (the live-claim condition); `claimBatch`: the same condition and `SKIP LOCKED` | F2 |
| LS2 | An ack, release, bury or hold that carries a token other than the row's current one changes nothing and reports `ClaimLost`; a hold that succeeds keeps the row locked to the end of the caller's transaction, so another consumer's claim waits. | the token condition in each settle statement; `FOR NO KEY UPDATE` in the hold | F3, F4 |
| LS3 | Delivery is at least once, with no order across rows; a provider can hear of a row twice when its send succeeded and the ack did not commit. | a claim never marks the row delivered; the lease lapses | F6 |
| LS4 | `ack` is one conditional write that joins the caller's transaction when there is one. | one statement, no session state | F5 |
| LS5 | Receipts and a sweep wake a row without `LISTEN`; a row ends `dead` only after a recorded failure class (and, in `release`, after the declared attempts). | `queued_at`, `stale`, the `dead` CHECK, the `release` statement | F7, F9 |

Also: the `claim_token` is identity; `attempts` rises at each claim, so it is the **monotonic fencing number** that a downstream system can check (Kleppmann, "How to do distributed locking"). The fence protects the row, not the world: a worker that outlives its lease can still do its side effects, and only a system that checks the number can refuse them.

## The schema

A declaration yields one table (`<table>`; the name is validated as a simple lower-case identifier, so no statement needs quoting):

```sql
CREATE TABLE outbox (
  id              bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  kind            text        NOT NULL,                -- CHECK (kind IN (…)) when the declaration lists the kinds
  dedupe_key      text,
  payload         jsonb       NOT NULL,
  status          text        NOT NULL DEFAULT 'pending',
  attempts        integer     NOT NULL DEFAULT 0,
  claim_token     uuid,
  claimed_until   timestamptz,
  next_attempt_at timestamptz NOT NULL DEFAULT statement_timestamp(),
  queued_at       timestamptz,                         -- the transport's receipt
  settled_at      timestamptz,                         -- set when the row is delivered or dead
  last_error      text,                                -- a class of the declaration's closed set, never provider text
  created_at      timestamptz NOT NULL DEFAULT statement_timestamp(),
  CONSTRAINT outbox_status       CHECK (status IN ('pending', 'delivered', 'dead')),
  CONSTRAINT outbox_attempts     CHECK (attempts >= 0),
  CONSTRAINT outbox_lease        CHECK ((claim_token IS NULL) = (claimed_until IS NULL)),
  CONSTRAINT outbox_claim_open   CHECK (claim_token IS NULL OR status = 'pending'),
  CONSTRAINT outbox_settled      CHECK ((status = 'pending') = (settled_at IS NULL)),
  CONSTRAINT outbox_dead_class   CHECK (status <> 'dead' OR last_error IS NOT NULL),
  CONSTRAINT outbox_error_class  CHECK (last_error IS NULL OR last_error IN (…))
);
CREATE INDEX outbox_due ON outbox (next_attempt_at) WHERE status = 'pending';
CREATE UNIQUE INDEX outbox_dedupe ON outbox (kind, dedupe_key) WHERE dedupe_key IS NOT NULL;
COMMENT ON TABLE outbox IS 'pg-outbox schema 1';
```

Differences from the research's sketch, each with its reason: `settled_at` replaces `delivered_at` (one timestamp for both endings, so retention has one clock; the `delivered iff` CHECK becomes `pending iff unsettled`); `outbox_claim_open` (a token or lease only exists on a pending row, so the `status = 'pending'` conditions of the settle statements are defence, not load-bearing, and the table cannot hold a claimed delivered row); `last_error` is CHECKed against the declaration's closed set (F13 is then store-enforced, not only typed); defaults use `statement_timestamp()`, the one clock of the library (below).

## The statements

All durations are bind parameters in milliseconds, cast `float8 * interval '1 millisecond'`. Time is `statement_timestamp()` of the database: the one clock, so relays on different machines agree, and it is stable inside a statement (the re-check of a `WHERE` after a row-lock wait uses the statement's own instant) and advances between statements of one transaction. A test makes a lease lapse at once with `leaseMs = 0`.

| Operation | Statement (shape) | Result | Transaction | Catalogue rows | Read |
| --- | --- | --- | --- | --- | --- |
| `enqueue` | `INSERT … ON CONFLICT (kind, dedupe_key) WHERE dedupe_key IS NOT NULL DO NOTHING RETURNING id` | `Enqueued(id)` / `Duplicate` | **requires** | `on-conflict` | no |
| `claimById` | `UPDATE … SET claim_token = gen_random_uuid(), claimed_until = ts + lease, attempts = attempts + 1 WHERE id = $1 AND status = 'pending' AND next_attempt_at <= ts AND (claimed_until IS NULL OR claimed_until <= ts) RETURNING …` | row, or none → `classify` | standalone | `outbox-lease` | no |
| `classify` (after a miss) | `SELECT status, ms until the lease ends, ms until due FROM … WHERE id = $1` | `Held(ms)` / `NotDue(ms)` / `Settled` | standalone | `outbox-lease` | **yes** |
| `claimBatch` | `WITH due AS (SELECT id … ORDER BY next_attempt_at, id FOR UPDATE SKIP LOCKED LIMIT $1) UPDATE … FROM due …` | rows | standalone | `outbox-lease`, `skip-locked` | no |
| `ack` | `UPDATE … SET status = 'delivered', settled_at = ts, token = NULL … WHERE id = $1 AND claim_token = $2 AND status = 'pending'` | `Delivered` / `ClaimLost` | **joins** | `outbox-lease` | no |
| `release` | one `UPDATE` that clears the claim, records the class (`COALESCE($3, last_error)`), and either moves `next_attempt_at` or, when `attempts >= $maxAttempts` **and** a class is on record, ends the row `dead` | `Released` / `Buried` / `ClaimLost` | joins | `outbox-lease` | no |
| `bury` | `UPDATE … SET status = 'dead', last_error = $3 … WHERE id = $1 AND claim_token = $2` | `Buried` / `ClaimLost` | joins | `outbox-lease` | no |
| `holdClaim` | `SELECT id … WHERE id = $1 AND claim_token = $2 AND status = 'pending' FOR NO KEY UPDATE` | `Held` / `ClaimLost` | **requires** | `row-locks` | no |
| `markQueued` | `UPDATE … SET queued_at = ts WHERE id IN (the ids) AND status = 'pending'` | count | standalone | `outbox-lease` | no |
| `stale` | `SELECT id … WHERE status = 'pending' AND no live claim AND greatest(coalesce(queued_at, created_at), next_attempt_at) <= ts - $1 ORDER BY id LIMIT $2` | ids | standalone | `outbox-lease` | **yes** |
| `counts` | `SELECT status, count(*) … GROUP BY status` | counts | standalone | `outbox-lease` | **yes** |
| `open` | `SELECT id, kind, attempts, last_error, ms until due, ms since receipt … WHERE status = 'pending' ORDER BY id DESC LIMIT $1` | rows, never the payload | standalone | `outbox-lease` | **yes** |
| `cleanup` | `DELETE … WHERE id IN (SELECT id … WHERE status IN ('delivered', 'dead') AND settled_at <= ts - $1 ORDER BY id LIMIT $2)` | count | standalone | `outbox-lease` | no |

**Transaction column.** `requires`: meaningless outside the caller's transaction (`enqueue` commits alone otherwise, which is the dual-write gap; a hold outside one holds nothing); an adapter takes the transaction as a parameter or in its type. `joins`: one conditional write that commits with the caller's transaction when there is one and alone otherwise. `standalone`: must **not** run in a caller's transaction: a claim that sits in an open transaction is invisible to every other claimer until it ends, and holds its row lock while the worker sends.

**Ids, tokens, payloads.** An id is a branded decimal string (`bigint` exceeds `Number`); a token is a branded string; `payload` is sent as `$n::jsonb` text and read back as `payload::text`, so no driver's JSON rule decides the encoding. Timestamps never cross the boundary: the statements return milliseconds. Every other column a decoder reads is checked; a row that does not have the shape is a `ProtocolError` (a defect: the schema and the statements disagree).

**`release` and the attempt policy.** `retry: { maxAttempts, delaysMs }` is data in the declaration. After a failed send the worker calls `release` with the class it observed, or none when no provider produced one (an outage of the worker's own side). The row ends `dead` only when `attempts >= maxAttempts` **and** a class is on record (this call's or an earlier one's); an outage never burns a row. A poison payload is `bury`'d at once with its class. The next attempt is due after `delaysMs[min(attempts, n) - 1]` (or the caller's `retryAfterMs`). Both `release` and `bury` clear the claim.

**The closed set of classes.** `errorClasses` is a non-empty list in the declaration, a union type in the API, and a CHECK in the table. There is no way to store `String(error)`.

## The mode check

Each operation lists the catalogue rows it rests on (table above). `operationSupport(mode, id)` is the weakest cell of its rows in the mode's column (`works` is `yes`, `unknown` is `unverified`, anything else is `no`; pg-txmode keeps that mapping private, so it is repeated in one function and a test pins it to `capabilities`' for the rows that both name), and a **read** is capped at `unverified` on a mode whose `capabilities(mode).cachesReads` is true (Hyperdrive: reads are cached and a write does not purge them). `requireOperation(mode, id, { allowUnverified })` throws `UnsupportedOperationError`, quoting the catalogue cell. Every statement a read uses calls `statement_timestamp()`, which Hyperdrive's documentation lists as a function that makes it skip its cache; nothing was run through Hyperdrive, so the cell stays `unverified`. A claim by id works wherever PgBouncer does and is the Hyperdrive-safe claim (it uses no `SKIP LOCKED`); a batch claim is `unverified` there.

| Mode | Status |

| Session pooling, direct | works; the library uses no session feature |

## What is not supported

`LISTEN/NOTIFY`, session advisory locks, logical replication, `COPY`, named prepared statements that the pooler does not track (F8 lints every statement in every mode); a worker runtime, cron, flows, dashboards, rate limits (use Effect's queue or effect-mq); ordering across rows or per key (delivery is unordered; a later spec can add a per-key rule); exactly-once delivery (effects must be idempotent; the row id is the key); broker clients in the core (a transport publishes ids after commit and the receipt is recorded with `markQueued`); payload encryption and personal-data policy (the caller owns what goes into `payload`); an inbox (exactly-once processing); databases other than PostgreSQL; concurrency claims on PGlite (it runs every statement on one session, so races prove nothing there); isolation levels above READ COMMITTED (the fence relies on a second claimer re-reading the row after the lock wait; under REPEATABLE READ the loser gets 40001 instead of an empty result).

## The model

`model/ClaimFence.tla` models one row, `Workers` workers and a clock: the actions `Tick`, `Claim`, `Send`, `Ack`, `Release` (with or without a class), `Bury`, `Hold`, `CommitAck`, `CommitNoAck`, `Abort`, `Crash`. Each action is tagged `\* @operation <id>` with the id of the operation it models; a test fails when an id in the code has no action, or the reverse. Switches (`Fence`, `LiveCheck`, `MarkAtClaim`, `ClassRule`, `HoldLocks`, `Lease`) turn each protocol rule off in a `.cfg` of its own. Invariants: `AtMostOneLiveLease` (LS1), `NoStaleSettle` (LS2), `HoldExcludesClaims` (LS2), `DeliveredWasHeard` (LS3), `DeadNeedsClass` and `DeadAfterAttempts` (LS5), `LeaseIsFinite` (no stuck row after a crash). `model/cases.json` lists each case with its expected result and, for a broken variant, the conformance control that mutates the same rule in SQL. `bun run model` runs TLC on every case and fails when the correct model has an error or a broken variant has none. TLC checks the model; it does not check the SQL. The tie is by operation id and by a digest of `packages/core/src/**`, recorded in `model/confirmed.json`: a change to the covered files fails `bun run model` until the model's action for the changed statement is re-read and the digest re-recorded (the method of vektorprogrammet's `verify-membership-writes --code`). That is a test-rung edge, not a generated one; the model is not generated from the declaration (a decision: the correspondence between a TLA+ action and a SQL statement is a reviewed claim).

## Falsifiers

Each runs on PostgreSQL directly and behind PgBouncer in transaction mode (Neon's settings, a pool of 2 server connections, so concurrent clients really swap connections). A race runs `ROUNDS` fresh rounds (default 100; `PG_OUTBOX_ROUNDS=300` for the heavy run), each on a freshly truncated table, and prints the loser's `Cause` when it fails. A negative control is a mutation of the statement text (applied at the executor, never to the product source) that **must** make the falsifier fail; a mutation that does not change the text fails the test (no vacuous control).

| # | Falsifier (must hold) | Negative control (must fail) |
| --- | --- | --- |
| F1 | A rolled-back business transaction leaves no row; a committed one leaves one, with its id | `enqueue` on its own connection: the row survives the rollback |
| F2 | Of N concurrent claimers of one row exactly one gets `Claimed`, the rest `Held`; batch claimers take disjoint sets that add up to every row; a row claimed in an open transaction is skipped by a second batch claim, which takes the next row instead of waiting | remove the live-claim condition from `claimById`; remove it from `claimBatch`; remove `SKIP LOCKED` |
| F3 | After the lease lapsed and a second claimer took the row, the first claimer's `ack`, `release`, `bury` and `holdClaim` all answer `ClaimLost` and change nothing; a lapsed lease that nobody took over does not stale its token | `ack` without the token condition; `release` without it |
| F4 | A hold inside a transaction keeps the row locked: a competing claim waits until the transaction ends and then misses (acked) or takes the row (not acked); a stale token's hold answers `ClaimLost` | a hold that locks nothing (`SELECT` without `FOR NO KEY UPDATE`) |
| F5 | `ack` in the caller's transaction: its rollback rolls the ack back (the row is still claimed and pending); its commit commits both | `ack` on its own connection: it survives the rollback |
| F6 | A worker that claims and never acks does not lose the row: it is claimed again after the lease (`attempts` 2); while the lease is live nobody else gets it | a claim that marks the row delivered (the old relay) |
| F7 | A class is recorded and the next attempt waits for its date (both claims); the row ends `dead` only when `attempts >= maxAttempts` **and** a class is on record; a release with no class never ends it; `bury` needs a class | end the row by attempt count alone; drop `next_attempt_at <= ts` from each claim |
| F8 | Every statement of the library passes `@pg-txmode/lint` with no error in every mode (no `LISTEN`, no session advisory lock, no `SET`, no named statement); the recorded statement log of a full journey has no finding | add a `LISTEN` to a statement: the lint fails |
| F9 | `markQueued` records the receipt; the sweep (`stale`) lists a pending row with no live claim and no receipt within the threshold, and does not list it again until the threshold passes after the next receipt | the sweep without the receipt term lists the row again at once |
| F10 | `cleanup` deletes only terminal rows older than the TTL, at most `limit` at a time, never a pending or claimed row | delete with no status filter |
| F11 | The model: the correct configuration has no error; each broken variant (no fence, no live check, mark at claim, no class rule, a hold that locks nothing, no lease) has the counterexample its case names; the operation ids of the model and of the code are the same set; the covered digest is current | the broken variants themselves; an id removed from the model |
| F12 | A mode that caches reads (Hyperdrive) refuses the four read operations unless `allowUnverified` is set, and `claimBatch` likewise; PgBouncer and direct accept every operation; every read statement calls an uncached function (checked with the lint's `uncachedFunctions`). Status of the Hyperdrive **behaviour**: unverified, nothing was run through it | remove `statement_timestamp()` from `stale`: the uncached-function check fails |
| F13 | `last_error` holds only a class of the closed set: the store refuses another text (23514), and the declaration refuses a class outside its set | a migration built without the CHECK accepts an address |
| F14 | A duplicate `(kind, dedupe_key)` is `Duplicate` and stores one row; an enqueue with no key never conflicts | a table without the unique index stores two |
| F15 | The typed answers of a miss are the truth: a live claim is `Held` with the remaining ms, a release with a future date is `NotDue`, a delivered, dead or absent row is `Settled` | `classify` that answers `Held` for every miss |
| F16 | The core imports nothing but `@pg-txmode/core`: no Effect, no driver (the boundary test of spec 0000 plus a manifest check) | add `import "pg"` to a file of `packages/core/src` |
| F17 | `bun run ready` exits 0 on the head | the controls above |

## Constraints on the implementation

- Free on mechanism, specific on behaviour: the statements may change as long as the journey and the falsifiers hold.
- Tests wait for the server's own clock only where a lease must lapse for real (a 300 ms lease, polling the claim for up to 5 s); everywhere else a lease of 0 ms stands for "lapsed".
- Nothing is published; every package is private.

## Risks

| Risk | Mitigation |
| --- | --- |
| Hyperdrive was not tried: its read cache, `claimById`, `FOR NO KEY UPDATE` and `ON CONFLICT` through it are unverified for this table | Every Hyperdrive cell says `unverified` and the mode check refuses it by default; the claim by id avoids the one unverified construct; pg-txmode's probe Worker (a wizard) is the only source of truth |
| The model is a claim about the SQL, not a proof of it | Said; the tie is by id and by digest, and every broken variant has a SQL control in the conformance suite that shares its name |
| The submodule pin hides changes in pg-txmode | Moving the pin is a reviewed diff; the pg-txmode catalogue rows the library rests on are named per operation |
| The database clock is one more thing to trust (a failover that steps it back would extend leases) | A lease is a bound on a worker's silence, not on correctness: the fence protects the row whatever the clock does; `attempts` is the fencing number for the rest |
| A claim by id costs a second statement on a miss | Only on a miss; the second is a read of one row by primary key |
| `Held` after a race may report 0 ms (the claim was released between the two statements) | Documented in the result; the caller looks again |

## Open questions for the operator

1. **Clock source.** The research leans to the app clock as a bind parameter (testable under Effect's `TestClock`); pg-txmode's merged pattern and this draft use the database's `statement_timestamp()` (one clock, no skew by construction; a test lapses a lease with `leaseMs = 0`). The Effect adapter can still pass the lease it wants. Say if the app clock is wanted instead: it changes the statements and the model's `Tick`.
2. **Ordering** (research decision 6): none in v1, as the research recommends.
3. **Dependency form**: the submodule above, until pg-txmode is published.
